# Seller Dashboard — Design Spec

> Только визуальная и UX-часть. Архитектура, данные, производительность, URL-состояние и этапы — в `plan.md`.

Дизайн-описание для учебного B2B-кабинета продавца. UI-кит: **HeroUI v3** (React Aria Components + Tailwind CSS v4, compound components).

> Названия и API компонентов HeroUI v3 сверяй с актуальной документацией (heroui.com) — библиотека молодая, часть имён и пропсов может отличаться от v2.

---

## 1. Принципы дизайна

1. **Плотность и скорость важнее украшений.** Это рабочий инструмент: продавец сидит в нём часами. Компактные таблицы, минимум декора, понятная иерархия.
2. **Состояние всегда видимо.** Фильтры, выбор, загрузка, ошибки — всё отражено в UI и (для фильтров) в URL.
3. **Три обязательных состояния у каждого блока:** loading (skeleton), error (с retry), empty (с подсказкой, что делать).
4. **Опасные действия — явные.** Архивирование и массовые операции требуют подтверждения или имеют undo.
5. **Оптимизм с честностью.** Optimistic update виден сразу, но при ошибке откат сопровождается понятным уведомлением.
6. **Используем компоненты HeroUI «как есть»**, кастомизация — через токены темы, а не через переопределение стилей компонентов.

## 2. Дизайн-токены и тема

Тема настраивается через CSS-переменные HeroUI v3 в `index.css`.

```css
@import 'tailwindcss';
@import '@heroui/styles';
```

| Токен             | Значение / решение                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------------- |
| Акцентный цвет    | Один основной (например, индиго/синий) — кнопки, активные табы, фокус                           |
| Семантика         | success — «Активен», warning — «Мало на складе», danger — «Ошибка/Архив», default — нейтральное |
| Фон приложения    | Светло-серый (светлая тема), тёмно-графитовый (тёмная)                                          |
| Поверхности       | Карточки/таблицы — на «приподнятой» поверхности с тонкой рамкой                                 |
| Радиусы           | Единый средний радиус (md) для инпутов, кнопок, карточек                                        |
| Типографика       | Системный sans / Inter; цифры — `tabular-nums` (цены, остатки, метрики)                         |
| Размеры контролов | В таблицах и тулбарах — `sm`; в формах и модалках — `md`                                        |
| Темы              | Light + Dark, переключатель в шапке, выбор хранится в localStorage                              |

Правила:

- Цвета статусов использовать только через семантические токены, не хардкодить hex.
- Денежные значения форматировать через `Intl.NumberFormat` (₽, без дробной части в таблице).
- Отрицательная динамика — danger, положительная — success, нейтральная — default.

## 3. Лэйаут приложения

```
┌──────────────────────────────────────────────────────┐
│ Header: логотип · название магазина · тема · профиль │
├────────────┬─────────────────────────────────────────┤
│ Sidebar    │ Page header (title + actions)           │
│  Products  │─────────────────────────────────────────│
│  Analytics │ Content                                 │
│            │                                         │
└────────────┴─────────────────────────────────────────┘
```

- **Sidebar** (240px, сворачивается в иконки на <1024px, на мобильных — Drawer): два пункта — Products, Analytics. Активный пункт подсвечен.
- **Header** — высота 56px, sticky.
- **Content** — max-width ~1440px, горизонтальные отступы 24px (16px на мобильных).
- **Page header** — заголовок, краткий счётчик (например, «48 213 товаров»), основные действия справа.
- Адаптивность: десктоп — приоритет; планшет — сворачиваемый sidebar; мобильный — таблица скроллится горизонтально, фильтры уезжают в Drawer.

Редактор товара — модалка или Drawer; роуты описаны в `plan.md`.

## 4. Страница Products

### 4.1 Структура

1. **Page header**: «Товары», счётчик, кнопка «Добавить товар» (опционально).
2. **Toolbar** (одна строка, переносится на узких экранах):
   - `SearchField` — поиск по названию/артикулу, debounce 300 мс, кнопка очистки.
   - `Select` — Категория.
   - `Select` — Статус (Все / Активен / Черновик / Архив).
   - `Select` или `Switch` — Наличие (Все / В наличии / Нет в наличии).
   - Кнопка «Сбросить фильтры» (видна только если есть активные фильтры).
   - Справа: `Select` сортировки (или сортировка по клику на заголовок столбца).
3. **Active filters row** — `Chip` с закрытием для каждого применённого фильтра (опционально, улучшает читаемость URL-состояния).
4. **Table** — основная область.
5. **Footer таблицы**: `Pagination`, выбор размера страницы (25 / 50 / 100), текст «1–50 из 48 213».
6. **Bulk Action Bar** — появляется при выборе товаров (см. 4.3).

### 4.2 Таблица

Компонент: HeroUI `Table` (на базе React Aria) + виртуализация для оптимизированной версии.

| Колонка   | Содержимое                                             | Особенности                                            |
| --------- | ------------------------------------------------------ | ------------------------------------------------------ |
| Чекбокс   | выбор строки; в шапке — «выбрать всё на странице»      | indeterminate-состояние                                |
| Товар     | миниатюра 40×40 + название + артикул (вторичный текст) | truncate в 1–2 строки                                  |
| Категория | текст                                                  |                                                        |
| Цена      | `1 290 ₽`                                              | выравнивание вправо, tabular-nums, сортируемая         |
| Остаток   | число                                                  | если 0 — danger-текст; если <10 — warning; сортируемая |
| Статус    | `Chip` (success / default / danger)                    |                                                        |
| Обновлён  | относительная дата                                     | tooltip с точной датой                                 |
| Действия  | `Dropdown`: Изменить, Архивировать                     | иконка «⋯»                                             |

Состояния строк:

- **Selected** — подсветка фона.
- **Pending (optimistic)** — слегка приглушённая строка + маленький спиннер/индикатор в колонке статуса.
- **Error после rollback** — краткая danger-подсветка рамки (1–2 секунды) + toast.
- **Archived** — приглушённый текст, чип «Архив».

Состояния таблицы:

- **Loading (первая загрузка)** — `Skeleton` на 10–15 строк с теми же колонками.
- **Refetching / смена страницы** — предыдущие данные остаются на экране, сверху тонкий progress-индикатор; таблица не «прыгает».
- **Empty (нет товаров)** — иллюстрация/иконка + «Товаров пока нет» + CTA.
- **Empty (ничего не найдено)** — «Ничего не найдено по этим фильтрам» + кнопка «Сбросить фильтры».
- **Error** — `Alert` (danger) с текстом ошибки и кнопкой «Повторить».

### 4.3 Bulk Actions

Появляется **sticky-панелью внизу экрана** (или над таблицей), когда выбран ≥1 товар.

```
[ ✕ ] Выбрано: 128   [Изменить цену] [Изменить остаток] [Статус ▾] [Архивировать]   Выбрать все 48 213
```

- «Изменить цену» / «Изменить остаток» → `Modal` с `NumberField` и режимом: _установить значение_ / _изменить на ±N_ / _изменить на ±N%_ (для цены).
- «Статус» → `Dropdown` со списком статусов.
- «Архивировать» → `Modal`-подтверждение с количеством товаров (danger-кнопка).
- «Выбрать все N» — ссылка-действие для выбора всех результатов фильтра (не только текущей страницы); при этом явно показывать, что выбрано N, а не только видимые.
- Во время операции: кнопки disabled, в панели — прогресс/спиннер.
- Результат: `Toast` — success («Обновлено 128 товаров») или error («Не удалось обновить 12 из 128» + «Повторить для неудачных»).
- Optimistic: цена/остаток/статус обновляются в таблице сразу; архивирование — тоже сразу, но с возможностью **Undo** в toast в течение ~5 сек.

### 4.4 Product Editor

Открывается в `Modal` (или `Drawer` справа — удобнее для просмотра таблицы рядом). Выбери один вариант и держи его единообразным.

Поля формы (HeroUI `Form`, `TextField`, `NumberField`, `Select`):

| Поле      | Контрол             | Валидация                                     |
| --------- | ------------------- | --------------------------------------------- |
| Название  | TextField           | обязательно, 3–120 символов                   |
| Цена      | NumberField (₽)     | обязательно, > 0, макс. 2 знака после запятой |
| Остаток   | NumberField         | целое, ≥ 0                                    |
| Категория | Select              | обязательно                                   |
| Статус    | Select / RadioGroup | обязательно                                   |

Поведение:

- Ошибки валидации показываются под полем (inline), после blur или при submit; первый невалидный инпут получает фокус.
- Ошибки API (400/409/500): общая ошибка — `Alert` в верхней части формы; серверные ошибки полей — привязываются к конкретным полям.
- Кнопки: «Сохранить» (primary, показывает спиннер и disabled во время мутации), «Отмена». «Сохранить» неактивна, если форма не изменена (dirty-check).
- При закрытии с несохранёнными изменениями — подтверждение.
- После успешного сохранения: закрыть, toast «Товар сохранён», строка в таблице обновилась (через invalidation/обновление кэша).
- Состояния загрузки данных товара: skeleton полей формы.

## 5. Страница Analytics

### 5.1 Структура

1. **Page header**: «Аналитика».
2. **Filters bar**:
   - Период: пресеты (7 дней / 30 дней / 90 дней / Свой период) — `Tabs` или `ButtonGroup`; для «Свой» — `DateRangePicker`.
   - Категория — `Select`.
   - Группировка графика (день / неделя / месяц) — `Tabs`.
   - Всё хранится в URL.
3. **KPI cards** — сетка 4 в ряд (2×2 на планшете, 1 колонка на мобильных).
4. **График продаж** — широкая карточка.
5. (Опционально) таблица «Топ-товары» — для демонстрации ещё одного независимого запроса.

### 5.2 KPI-карточки

Компонент: `Card`.

Содержимое:

- Название метрики (вторичный текст, sm).
- Значение (крупно, 28–32px, tabular-nums): Выручка, Заказы, Средний чек, Конверсия.
- Дельта к предыдущему периоду: `Chip` со стрелкой ↑/↓ и процентом (success / danger).
- Состояния: Skeleton (значение + дельта), Error (компактная ошибка с retry внутри карточки — **ошибка одной карточки не ломает остальные**), Empty («Нет данных за период»).

### 5.3 График продаж

- Библиотека графиков — отдельная (Recharts / visx / ECharts), стилизуется токенами темы (цвета через CSS-переменные).
- Линия/область выручки; tooltip с датой, выручкой и количеством заказов.
- Оси: даты по X, денежные значения (сокращённо: «120 тыс.») по Y.
- Состояния: Skeleton-прямоугольник той же высоты (чтобы не было layout shift), Error + retry, Empty.
- При смене фильтров — предыдущий график остаётся, поверх — лёгкое затемнение/индикатор.

## 6. Обратная связь и системные компоненты

| Задача                                      | Компонент HeroUI                     |
| ------------------------------------------- | ------------------------------------ |
| Уведомления (success/error/undo)            | `Toast`                              |
| Подтверждения, формы                        | `Modal` / `AlertDialog`              |
| Боковая панель редактора, мобильные фильтры | `Drawer`                             |
| Контекстные меню строк                      | `Dropdown`                           |
| Подсказки (точная дата, обрезанный текст)   | `Tooltip`                            |
| Статусы                                     | `Chip`                               |
| Загрузка                                    | `Skeleton`, `Spinner`, `ProgressBar` |
| Ошибки блоков                               | `Alert`                              |
| Навигация внутри страницы                   | `Tabs`                               |

Правила уведомлений:

- Success — автозакрытие 3–4 сек.
- Error — остаётся, пока пользователь не закроет, с действием «Повторить».
- Undo — 5–6 сек, с кнопкой «Отменить».
- Не показывать toast на каждое мелкое действие — только на мутации.

## 7. Доступность

- HeroUI v3 построен на React Aria — не ломать его: не оборачивать интерактивные элементы лишними `div` с обработчиками.
- Все иконочные кнопки имеют `aria-label`.
- Таблица: корректные заголовки, `aria-sort` на сортируемых колонках, выбор строк доступен с клавиатуры.
- Фокус-кольцо видно всегда; после закрытия модалки фокус возвращается на триггер.
- Контраст текста/статусов ≥ WCAG AA в обеих темах.
- Статусы не передаются только цветом — рядом всегда текст/иконка.
- Анимации уважают `prefers-reduced-motion`.

## 8. Производительность UI (только визуальная часть)

- Высота строк таблицы фиксирована (удобно для виртуализации и без layout shift).
- Skeleton'ы повторяют финальную геометрию блоков, чтобы не было скачков вёрстки.
- Смена страницы/фильтров не «схлопывает» контент: старые данные остаются на экране с индикатором обновления.

Техническая часть оптимизации, URL-состояние, структура кода и этапы — в `plan.md`.

## 9. Чек-лист готовности UI

- [ ] Light/Dark темы работают, токены не хардкодятся
- [ ] У каждого блока есть loading / error / empty
- [ ] Bulk-панель корректно показывает выбранное (страница vs все результаты)
- [ ] Optimistic-состояния и откат визуально различимы и сопровождаются уведомлением
- [ ] Форма редактора: inline-валидация, серверные ошибки, dirty-check
- [ ] Analytics: независимые состояния у каждой карточки и графика
- [ ] Клавиатурная навигация и aria-атрибуты проверены
